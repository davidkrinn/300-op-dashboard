# UX Vision

## Purpose of This File

This file defines the user experience vision for the Restaurant Franchise Executive Dashboard.

It should guide layout, storytelling, interaction behavior, visual style, and component decisions.

## Product Experience Statement

The dashboard should feel like a morning command center for a multi-state restaurant franchise operation.

It should combine:

- Executive briefing speed
- SaaS analytics utility
- BI-style interactivity
- AI-style decision support

Core question:

What do I need to know this morning, and where should I focus today?

## Design Philosophy

A useful dashboard does not only show data. It helps people act.

The product should help users answer:

1. What changed?
2. Why did it change?
3. Where is the risk?
4. Where is the opportunity?
5. What should we do next?

## Core UX Principle

Lead with insight. Support with data.

Start with a concise, prioritized morning brief before deep chart analysis.

## Target Audience

Primary users:

- Franchise owners
- Regional managers
- Operations leads
- Finance leads
- Legal leads
- Real estate leads

## User Mindset

Users are time-constrained. They need fast, credible, actionable context between meetings and operational reviews.

## Primary User Questions

Executive questions:

- Are sales up or down?
- Are costs controlled?
- Which stores are at risk?
- Which states or brands need attention?
- What should we do next?

Regional Manager questions:

- Which stores need intervention?
- Which costs are out of line?
- Which customer signals are worsening?
- Which visits and coaching actions should I prioritize?

## Desired Emotional Response

Users should feel:

- Oriented
- Confident
- In control
- Prepared to act

## Experience Metaphor

Executive briefing room for daily restaurant performance.

## Visual Style Direction

Preferred style: high-end consulting dashboard.

The UI should feel:

- Modern
- Polished
- Clear
- Strategic
- Easy to scan

It should avoid generic admin panel aesthetics and dense spreadsheet-like layouts.

## Dashboard Opening Experience

Above the fold should include:

- Page title and date context
- Global filters
- Morning brief
- 3-5 priority insights
- Compact KPI snapshot

The first screen should communicate overall condition, top risk, top opportunity, and immediate next focus.

## Recommended Executive Homepage Layout

1. Header and filters
2. Morning brief
3. Priority insight cards
4. KPI snapshot
5. Risk and opportunity summary
6. Regional map
7. Sales and order trends
8. Brand comparison
9. Channel mix
10. Regional performance table
11. Recommended actions

## Insight Card UX

Each insight card should include:

- Type
- Priority
- Headline
- Short explanation
- Affected stores or region
- Recommended action
- Confidence indicator
- Expandable details

Insight types:

- Performance
- Risk
- Opportunity
- Forecast

## KPI Card UX

Each card should include:

- Label
- Current value
- Change indicator
- Comparison period
- Status cue
- Optional sparkline
- Tooltip/helper text

## Store Risk UX

Store risk views should expose:

- Count of stores at risk
- Risk distribution
- Highest risk stores
- Primary risk drivers
- Recommended follow-up actions

Risk scores must be explainable, not opaque.

## Regional Opportunity UX

Opportunity views should answer:

- Where is upside?
- Why is it happening?
- What action should be taken?

## Map UX

Map interactions should support:

- State and brand filtering
- Risk overlays
- Cluster context
- Store clickthrough

Map should be decision-supporting, not decorative.

## Filters UX

Core filters:

- State
- Brand
- Region
- Store
- Time period
- Channel
- Risk level

Behavior:

- Keep filters near top
- Show active states clearly
- Support quick reset
- Make changes feel immediate

## Comparison UX

Enable clear comparisons for:

- Store vs store
- Store vs region
- Brand vs brand
- State vs state
- YoY movement

Use consistent scales, plain labels, and variance indicators.

## Channel Mix UX

Support channels:

- App delivery
- Driver delivery
- In-store
- Drive-thru

Expose channel trends and regional or brand differences.

## Regional Manager Deep-Dive UX

Regional page should prioritize interventions:

1. Regional health score
2. Top actions
3. Stores at risk
4. Cost variance
5. Labor and food exceptions
6. Ops quality trends
7. Complaint and rating trends
8. Demand drivers
9. Visit plan

## Store Detail UX

Store pages should answer:

- What is happening now?
- Is it improving or declining?
- Why?
- What should the manager do next?

## Insights Center UX

Support filtering by type, priority, state, and brand with searchable, expandable insight details.

## Forecasting UX

Forecast language should express probability and confidence, not certainty.

Use words like projected, expected, likely, and historically associated.

## Alerts UX

Alert prioritization should consider severity, impact, urgency, trend direction, and number of affected stores.

## Recommended Actions UX

Actions should be concrete and operationally specific.

Avoid vague language such as monitor situation.

## Color System

Use color with semantic meaning and label text:

- Purple accents: Taco Bell
- Red accents: Pizza Hut
- Green: positive
- Amber: watch
- Red: risk
- Blue: neutral operational insight
- Gray: baseline/supporting

## Typography, Layout, and Interaction

- Clear hierarchy for headings and KPI values
- Generous but efficient spacing
- Card-based grouping
- Purposeful hover and drilldown interactions
- Minimal motion used to support clarity

## Empty and Loading States

Provide meaningful empty-state guidance and stable loading skeletons to avoid layout shift.

## Accessibility

- Strong color contrast
- Not color-only status signaling
- Readable chart labels
- Semantic elements and keyboard-friendly controls

## Responsive Priorities

Desktop: full decision workspace.

Tablet: brief, priorities, KPIs, map/summary, risk.

Mobile: brief, high-priority alerts, top KPIs, risk list, recommended actions.

## UX Voice and Writing Style

Tone should be:

- Professional
- Direct
- Calm
- Action oriented

Insight writing should always include:

1. What happened
2. Where it happened
3. Why it may have happened
4. Why it matters
5. What action to consider

## UX Anti-Patterns to Avoid

- KPI overload
- Unexplained risk scores
- Chart-heavy pages without interpretation
- Hidden filters
- Decorative maps without decision value
- Forecast claims with false certainty

## Success Criteria

The UX is successful if users can quickly answer:

- Are we doing better or worse?
- Where are costs off target?
- Which stores are at risk?
- Where is opportunity?
- What should we do next?

## North Star

The dashboard should feel like a trusted operating partner: what changed, why it matters, and where to focus next.
